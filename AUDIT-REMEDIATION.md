# Результат исправления аудита от 30 июля 2026

Этот файл сопоставляет находки исходного статического аудита с изменениями в версии 6.1.

| ID | Статус | Что изменено |
|---|---|---|
| F-01 | Исправлено | Production запускается только с `SESSION_SECRET`/`JWT_SECRET` длиной не менее 32 байт. Самоподписанные cookies заменены случайными серверными сессиями, хеш которых хранится в Supabase. |
| F-02 | Исправлено | `/api/config` требует авторизацию. Постоянные TURN-пароли удалены; сервер выдаёт временные coturn REST credentials с TTL. |
| F-03 | Исправлено | `presence:query` проходит общий обработчик ошибок, принимает только массив, ограничивает число и формат ID. |
| F-04 | Исправлено для одного инстанса | Добавлены проверки payload, ограничения размера и per-user rate limits для сообщений, реакций, typing, presence и звонков. `maxHttpBufferSize` уменьшен до 64 КБ. Для нескольких инстансов всё ещё нужен Redis. |
| F-05 | Исправлено выбранной политикой | Добавлять участников может только владелец группы. Новый участник видит сообщения, созданные не раньше его `joined_at`. |
| F-06 | Существенно исправлено | Изображения декодируются через `sharp`, проверяются по реальному формату, размеру, пикселям и кадрам, перекодируются и очищаются от метаданных. Добавлена очередь повторного удаления. Профильный bucket остаётся публичным по продуктовой политике. |
| F-07 | Частично исправлено | Настроен `trust proxy` для Render, лимитеры разделены, ограничены по числу ключей и очищаются. Store остаётся локальным в памяти одного инстанса. |
| F-08 | Исправлено | Сессии хранятся и отзываются на сервере; logout закрывает связанные сокеты; есть idle и absolute timeout. |
| F-09 | Исправлено | Добавлены проверки Origin, CSP, HSTS в production, защита от iframe, MIME-sniffing, ограничение permissions и `Cache-Control: no-store` для API. |
| F-10 | Частично исправлено | Docker обновлён до Node.js 22, добавлен `.dockerignore`, процесс работает от `node`, версии верхнего уровня закреплены. `package-lock.json` нужно создать в рабочем npm-окружении и закоммитить. |
| F-11 | Не исправлено архитектурно | E2EE не добавлено. Ограничение явно описано в README и SECURITY. |
| F-12 | Исправлено | Presence отправляется только пользователям с общими чатами; произвольные ID не раскрываются; карта чужих `read_at` больше не выдаётся. |
| F-13 | Исправлено | Реакции ограничены серверным набором emoji, существующая карта очищается, видимое значение экранируется. |
| F-14 | Исправлено | `password_hash` выбирается только в login-пути; публичные запросы используют явные безопасные проекции. |
| F-15 | Исправлено как beta-policy | Самостоятельное включение Premium возможно только при `PREMIUM_BETA_ENABLED=true`; перед монетизацией переменную нужно отключить и подключить billing/admin flow. |

## Что ещё требуется перед production

1. Выполнить `supabase/schema.sql` в тестовом Supabase.
2. Запустить интеграционные тесты регистрации, входа, logout, сообщений, групп, звонков и загрузки изображений.
3. Выполнить `npm install`, проверить полученное дерево и закоммитить `package-lock.json`; затем использовать `npm ci --omit=dev` в Dockerfile.
4. При масштабировании Render больше чем до одного инстанса подключить Redis для Socket.IO adapter и общих rate limits.
5. Для обещания end-to-end encryption потребуется отдельный криптографический протокол и управление ключами на клиентах.
